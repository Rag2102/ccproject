# Artifact: budget-aware VM failure mitigation (v2) and VMMBench

This file is the artifact README for the v2 paper (plan Week 25). The course-project README (`README.md`) describes v1 and the live demo; nothing here changes v1.

Licence: Apache-2.0 (`LICENSE`, `NOTICE`). Citation: `CITATION.cff`.

## What is here

| Path | What it is |
| --- | --- |
| `vmsim/` | The simulator: worlds, failures, placement regimes, migration model, accounting, policies P0-P8 |
| `vmmbench/` | Result and scenario-card schemas with a dependency-free validator |
| `configs/v2/matrix.yaml`, `configs/v2/cards/` | The frozen evaluation matrix (PROTOCOL v1.0) and one scenario card per regime |
| `docs/v2/PROTOCOL.md` | The pre-registered protocol; every later change is in `docs/v2/CHANGES_AFTER_FREEZE.md` |
| `docs/v2/THEORY.md`, `vmsim/theory.py` | The break-even theory and its closed forms |
| `scripts/v2/` | Every step from raw data to the paper's numbers (numbered in the order they run) |
| `results/v2/`, `results/summary/` | Processed results that the figures, tables and `paper/numbers.tex` are built from |
| `paper/` | The paper source; every number is a macro generated by `scripts/v2/40_numbers.py` |
| `console/` | A static, read-only results viewer (`make console`, then open `console/index.html`) |

## Requirements

- Python 3.12 with the exact pins in `requirements.txt` and `requirements-dev.txt` (or `uv sync` with `uv.lock`).
- Or Docker: the `Dockerfile` builds a clean image from any commit.
- Measured on an Apple M5 laptop (10 cores, 16 GB, macOS 26.5). Any 8-core machine with 8 GB of free memory runs everything below; times scale with cores.

## Three ways to check the results

| Command | Time | What it does |
| --- | --- | --- |
| `make reproduce-small` | about 4 min | 300 hosts, seeds 1-3: reduced F4, F5, F8 and Table 3 with every summary, from the committed extracts only |
| `make docker-repro` | about 10 min (plus the image build) | The same inside a clean container built from `git archive HEAD`, then compares its Table 3 with this machine's copy |
| `make reproduce` | about 14 h on 8 cores | The full frozen matrix (2,000 hosts, 30 evaluation seeds), Week 20 ablations and sensitivity, seed replication (seeds 1001-1030) and the second placement source, then statistics, figures and numbers |

Expected outputs of `make reproduce-small`:
- `results/small/summary/`: `A.json` … `E.json`, `confirmatory.json`, `pareto.json`, `adaptive_D.json`, `table3.csv`, `table3.tex`, `vmconsole.json`.
- `results/small/figures/`: `v2_F4_advantage.pdf`, `v2_F4_advantage_other_budgets.pdf`, `v2_F5_pareto.pdf`, `v2_F8_adaptive.pdf`.

The small run is a smoke test of the pipeline, not a result: at 300 hosts and three seeds the confirmatory family cannot reach significance, and Holm p-values print as 1.000.

## Raw data

The small and full reproductions run from extracts committed to the repository (`data/processed/`). Rebuilding those extracts from the original sources needs about 100 GB of downloads:

```
scripts/v2/fetch_data.sh
```

It downloads Backblaze Drive Stats (45 ZIPs, 35.1 GB) and Google ClusterData 2019 cells a, b, h and f (66 GB in total; every shard is checked against the bucket's MD5). `scripts/v2/verify_checksums.py` then checks everything against `data/CHECKSUMS.sha256`. Raw third-party data is never redistributed here; the terms of each source are in `docs/v2/data_sources.md`.

## From results to paper

```
make stats figures numbers paper
```

`make numbers` writes `paper/numbers.tex`. `40_numbers.py --strict` fails if any number in the paper is still a placeholder, and `tests/v2/test_paper_numbers.py` fails if the paper uses a macro that the script does not define.

## Determinism

Every world is generated from its seed and hashed (scenario cards record the hashes), and every policy sees the same failures, arrivals and lifetimes for a given seed (common random numbers). Re-running a cell gives the same record bit for bit on the same platform. Across platforms, BLAS differences can move the last digits of the tuned threshold; `make docker-repro` reports any difference at the table's display precision.
