# Data sources

Every external dataset v2 uses: where it is, its terms, when it was accessed, and how to check that a local copy is the same. Bibliography keys refer to `paper/refs.bib`.

## 1. Backblaze Drive Stats (Weeks 4-5; hazard model)

| Field | Value |
| --- | --- |
| Page | https://www.backblaze.com/cloud-storage/resources/hard-drive-test-data |
| Files | 45 ZIP archives at `https://f001.backblazeb2.com/file/Backblaze-Hard-Drive-Data/<name>.zip`: `data_2013`, `data_2014`, `data_2015` (annual), then `data_Q1_2016` to `data_Q2_2026` (quarterly). Each holds one CSV per day, one row per drive |
| Size | 35.1 GB compressed (Content-Length of each archive, 4 Oct 2026); about 10× that as CSV |
| Accessed | 4 Oct 2026 (download started 15:08 IST) |
| Terms (re-read on the download day) | The page asks users to cite Backblaze as the source, to accept that they are solely responsible for how they use the data, and allows selling derivative works but not the data itself |
| Bib key | `backblaze2026drivestats` |
| Schema files | `Drive_Stats_Schema_Current.csv` (last updated Q2 2024) and `Drive_Stats_Schema_2018_Onward.csv` at the same file prefix |
| Checksums | SHA-256 of every archive and every Parquet file: `results/v2/backblaze_archives.csv` and `data/v2/backblaze/manifest.csv` (the manifest is regenerated by the ingest; the archive table is committed) |
| Local copy | `data/v2/backblaze/raw/*.zip` (kept, so Parquet can be rebuilt without a new download), `parquet/<year>_Q<n>.parquet` (kept columns only), both outside Git |
| Pipeline | `scripts/v2/10_backblaze_ingest.py` (resumable; row counts checked against the CSVs) |

Schema history, from Backblaze's schema-change file:
- from 2023 Q2 the files add `vault_id`, `pod_id` and `is_legacy_format`;
- from 2023 Q3 they also add `datacenter`, `cluster_id` and `pod_slot_num`.

These columns give a real drive-to-group mapping for the most recent three years. The quality report (section 6) gives the group sizes.

The page also offers the same data as an Apache Iceberg table in a public B2 bucket, with read-only keys published on the page. It is not used here: the ZIPs are the versioned, checksummable form.

v1 used a third-party per-drive summary of 2013-2017 (`data/raw/backblaze/backblaze_2013_2017_hdd_survival.csv`, 122,619 drives) with no licence file. v2 rebuilds everything from the archives above. `results/v2/backblaze_v1_sanity.json` compares the two.

## 2. Google ClusterData 2019 (Weeks 6 and 8; empirical ρ)

| Field | Value |
| --- | --- |
| Description | Borg traces of 8 cells (a-h), May 2019, 31 days, 96.4k machines (Tirmazi et al., Table 1) |
| Documentation | https://github.com/google/cluster-data/blob/master/ClusterData2019.md; "Google cluster-usage traces v3" (J. Wilkes, revised 2020-08-18, linked there); `clusterdata_trace_format_v3.proto` in the same repository |
| Terms | CC-BY 4.0 for the data and the documentation ("By downloading it or using them, you agree to the terms of this license") |
| Bib keys | `googleclusterdata2019` (data), `tirmazi2020borg` (paper describing it) |
| Accessed | 4 Oct 2026 (documentation, schema files and bucket listings; no trace data downloaded yet) |
| BigQuery | Project `google.com:google-cluster-data`, datasets `clusterdata_2019_a` to `clusterdata_2019_h`, tables `machine_events`, `machine_attributes`, `collection_events`, `instance_events`, `instance_usage`. The data is free, but queries are billed to your own project; the documentation asks users to sample while developing queries |
| Download | Public buckets `gs://clusterdata_2019_<cell>/`, each table sharded as `<table>-NNNNNNNNNNNN.json.gz` and `.parquet.gz`. Schemas in `gs://clusterdata_2019_schema/` |
| Sizes (listed 4 Oct 2026, Parquet) | `instance_events` 21.2 GB for cell a, 175.7 GB for all 8; `collection_events` 0.8 / 3.5 GB; `machine_events` and `machine_attributes` under 0.1 GB; `instance_usage` 437.6 GB / 3,395 GB (not needed) |
| Plan | Download `machine_events`, `machine_attributes` and `instance_events` for one cell at a time, aggregate to placements (`docs/v2/rho_definition.md`), and delete the raw shards. No BigQuery scans are needed, so the cost question in the plan does not arise. Downloading is a Week 8 step and needs a go-ahead with its size, like the Backblaze download |
